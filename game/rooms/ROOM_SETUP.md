# Room Setup

1. Create a new GameMaker project in the IDE.
2. Create rm_overworld and document the chosen room size.
3. Create a placeholder top-down player sprite and assign it to obj_player.
4. Create solid collision objects or configure tilemap collision. Movement must use the project's actual collision system. The player code in this repository refers to a solid object by the exact name `obj_solid` (an empty object with a collision mask, parented to nothing), so create it with that name or change the `place_meeting` calls in obj_player/Step.gml to match your collision setup.
5. Add one obj_game_controller (Create and Step events), one obj_hud (Create and Draw GUI events), one obj_status_menu (Create, Step and Draw GUI events) and one obj_player to rm_overworld. C opens the status menu. The controller loads the save once on room start and autosaves after each victory; it needs to be in the first room so the load happens at launch.
6. Create obj_npc (Create, Step and Draw events) with `dialogue_id` set to `"npc_hermit"` or `"sign_ruins"`, and place it in rm_overworld. For the Hermit's quest chain set `dialogue_id_after = "npc_hermit_after"` and `dialogue_id_final = "npc_hermit_checkoff"`; place a second obj_npc for the door with `dialogue_id = "ruin_door"` and `npc_kind = "prop"`. Face it and press Z to talk; obj_dialogue_box (Create, Step, Draw GUI and Destroy events) is created by the code, never placed by hand. Place one obj_merchant in rm_overworld too: facing it and pressing Z opens the shop. obj_shop (Create, Step, Draw GUI and Destroy events) is created by the code, never placed by hand.
7. For battles, create obj_battle_controller (Create/Step/Draw GUI/Destroy events) and start it with `scr_battle_start("bandit")` from a trigger. The prototype battles as an overlay in the current room, so no room transition is needed; create rm_battle_test only if you want to test the battle in isolation.
8. Create obj_enemy (Create and Step events) with enemy_id set to `"bandit"` or `"fallen_knight"`, and place instances in rm_overworld. Touching one starts the battle; a victory removes it from the room.
9. For the ruin slice, create rm_dungeon1 and place one obj_room_entry in it and in rm_overworld. Add obj_room_marker instances named to match the code: `ruin_start` at the entrance the door leads to, plus one marker per encounter from `scr_ruin_encounters()` (`ruin_bandit_a`, `ruin_bandit_b`, `ruin_knight`, `ruin_rare`). Put an obj_enemy on each encounter marker with the matching `enemy_id`, and a last obj_enemy with `enemy_id = "ruin_warden"` at the end of the room.
10. Place one obj_ruin_door in rm_overworld where the door belongs. It is the only way in: it refuses while `npc_hermit_quest_done` is unset and fades to rm_dungeon1 once it is. obj_room_transition and obj_room_marker are created by code and by placement respectively; do not place obj_room_transition by hand.
11. Compile and run before adding more systems.
12. For test builds, add one obj_debug_menu to rm_overworld: F10 toggles it, UP/DOWN + ENTER spawns an enemy ahead of the player, TAB switches to teleport, where you type `x,y` and press ENTER, B starts a Bandit battle, and F5/F9 save and load. Remove the object from release builds.

Do not fabricate .yy/.yyp metadata. Let GameMaker create resources. This document does not prove the project compiles.
